# Edison engineering contract

Read `docs/PROJECT.md`, `docs/JUDGING.md`, `docs/IMPLEMENTATION.md` and `docs/CURRENT_STATE.md` before substantial changes.

- Preserve the approved scope and Light Research Lab direction. Fundamental scope, design, publication and submission decisions remain with Emma.
- Research workbench, not a predictor or trading system. No orders, accounts, live feed, paid Jev fallback or invented evidence.
- Native-stock results are not token-market results. Preserve negative outcomes; distinguish recorded decisions from new navigation requests.
- Never read reserved 2025 native-stock or September–October 2026 token data for tuning.
- Keep raw captures, derived research bundles, credentials and recordings out of Git. Access is not redistribution permission.
- Runtime-validate typed evidence. Model output selects only allowlisted views; code supplies facts and numbers.
- Do not log questions, provider bodies or credentials. Bound inputs, timeouts and requests; no retries.
- Use actual shadcn/ui primitives. Preserve responsive, keyboard, theme, reduced-motion and print behavior.
- Run lint, type checks, tests, build and publication scans. Browser testing requires approval; a build is not visual validation.
- Feature branch only. No merge, deployment, paid narration or submission without approval. Keep current-state documentation honest.
